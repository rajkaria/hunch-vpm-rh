# 03 · Contracts

Foundry project under `contracts/`. solc 0.8.28, optimizer 200 runs, `via_ir = false`,
`evm_version = "cancun"` (Robinhood Chain Stock Tokens use post-Shanghai opcodes; the
chain's supported version is recorded in `08-deployment.md`). No upgradeable proxies.
`block.number` on this chain is the **L1 (Ethereum) block estimate**, which advances
about every 12 s while L2 blocks come every ~100 ms. The reference uses `block.number`
for vintages and we keep it (reference equivalence): a vintage is therefore every entry
with the same L1 block number, a ~12 s batch, which only widens the no-ordering-games
window. All timing (freeze, bells, timeouts) uses `block.timestamp`.
No external dependencies in production contracts except a minimal `IERC20` /
`IERC20Permit` / `AggregatorV3Interface` declared locally.

## HunchVPM.sol — the product settler

`HunchVPM` is `reference/VestedParimutuel.sol` copied and changed by the ten diffs below
and nothing else. `contracts/DIFF.md` holds the literal `diff -u` against the reference,
regenerated by `scripts/diff-reference.sh` in CI; CI fails if the diff contains a hunk
not listed here. The differential suite (`07-testing.md` §T3) proves that with
`feeBps = 0`, `maxEntry = 0`, `minEntry = 0` and entries unpaused, HunchVPM and the
reference produce identical `accepted`, payouts, refunds and residue on all 118 vectors
and on fuzzed sequences (the test contract standing in as the factory, D10).

### Constructor

```solidity
constructor(address guardian_, address treasury_, address factory_, address pauser_)
```
- `guardian` — may pause/unpause **new entries and new markets**, and name the pauser
  (D10). Immutable address (the Safe).
- `treasury` — receives swept fees. Immutable (the Safe).
- `factory` — the only address that may `create` a market (D10). Immutable: DeployRH passes
  the address the factory is about to be deployed at and checks it afterwards.
- `pauser` — may pause, never unpause (D10). Zero for none; the guardian replaces it.
Guardian, treasury and factory non-zero, checked.

### D1 · Fee on winners' gains

- `create(...)` gains a `uint16 feeBps` argument (≤ 500, else `FeeTooHigh`). Stored in
  `Market`.
- In claim of a **winning** position: `gain = payout − accepted` (payout ≥ accepted by
  P2 when the position is on the winning outcome), `fee = gain * feeBps / 10_000`
  (floor). The owner receives `payout − fee + refund`. `m.paidOut += payout` (gross,
  so residue arithmetic is unchanged), `feesAccrued[token] += fee`.
- No fee on: losing positions (payout 0), voided markets, refused remainders, residue.
- `sweepFees(IERC20 token)`: anyone; transfers `feesAccrued[token]` to `treasury`,
  zeroes it. Separate from claims on purpose: a treasury transfer can never make a
  claim revert.
- Events: `FeeAccrued(uint256 indexed positionId, uint256 fee)`,
  `FeesSwept(address indexed token, address indexed to, uint256 amount)`.

### D2 · Anyone can deliver a claim, only to its owner

- `claimFor(uint256 positionId)` and `withdrawRefundFor(uint256 positionId)`:
  permissionless; identical logic to `claim` / `withdrawRefund`; funds always go to
  `positions[id].owner`, never to `msg.sender`.
- Implemented by refactoring the bodies into `_claim(positionId)` /
  `_withdrawRefund(positionId)` that pay `p.owner`; `claim` / `withdrawRefund` keep the
  owner check (reference behaviour) and call the same internals.
- Why: the keeper pushes every payout after resolution, so a bettor never has to come
  back to collect. Judges see money arrive.
- Claims stay per position. Paxos can freeze any USDG address; a frozen winner's
  `claimFor` reverts alone and never blocks anyone else's (the keeper sends one call per
  position, or Multicall3 `aggregate3` with `allowFailure = true`).

### D3 · Beta bounds per market

- `create(...)` gains `uint128 minEntry, uint128 maxEntry` (0 = no bound). Immutable per
  market. `enter` reverts `EntryTooSmall` / `EntryTooLarge` on the **offered** amount.
- Venue values: min 1 USDG, max 100 USDG. The factory enforces a floor of at least
  `MIN_ENTRY` (1 USDG) and a non-zero cap at or above the floor (`EntryBoundsTooLoose`,
  `InvalidEntryBounds`), so filling a vintage to block entries costs real capital.

### D4 · Entries pause (guardian), nothing else pausable

- `setEntriesPaused(bool)`: only `guardian` (D10: the `pauser` may call it with `true`).
  Global. Emits `EntriesPaused(bool)`.
- Only `enter` / `enterWithAuthorization` (and, D10, `create`) check it (`EntriesArePaused`). `finalizeVintage`,
  `resolve`, `voidMarket`, `claim`, `claimFor`, `withdrawRefund`, `withdrawRefundFor`,
  `claimResidue`, `sweepFees`, `transferPosition` never check it. A test asserts each of
  these succeeds while paused (`07-testing.md` T2.9).
- Nothing else is privileged in HunchVPM. There is no owner, no upgrade, no price input,
  no way to move a stake.

### D5 · Gasless entry with a signed USDG transfer (EIP-3009)

USDG on chain 4663 implements EIP-3009 `receiveWithAuthorization`, including the
`bytes`-signature overload that accepts ERC-1271 smart wallets (verified in
`research-facts.md` §2). So a bettor never needs ETH:

```solidity
bytes32 public constant ENTER_TYPEHASH =
    keccak256("HunchEnter(uint256 marketId,uint8 outcome,uint256 amount,bytes32 salt)");

/// The nonce the bettor signs into USDG's ReceiveWithAuthorization. It binds the
/// market, the side and the amount, so whoever relays the signature cannot change them.
function enterNonce(uint256 marketId, uint8 outcome, uint256 amount, bytes32 salt)
    public view returns (bytes32)
{
    return keccak256(abi.encode(ENTER_TYPEHASH, block.chainid, address(this),
                                marketId, outcome, amount, salt));
}

function enterWithAuthorization(
    address from, uint256 marketId, uint8 outcome, uint256 amount,
    uint256 validAfter, uint256 validBefore, bytes32 salt, bytes calldata signature
) external nonReentrant returns (uint256 positionId);
```
- Anyone may call it (the venue's relayer normally does and pays the gas, about
  $0.004). The position's owner is `from`, never `msg.sender`.
- Order: all `enter` checks (open, not frozen, outcome, bounds, not paused) → vintage
  roll → book the position for `from` → `USDG.receiveWithAuthorization(from,
  address(this), amount, validAfter, validBefore, enterNonce(...), signature)`. USDG
  requires `to == msg.sender`, so the authorization cannot be redirected.
- **Real USDG does not revert on a used or cancelled nonce**: it emits
  `AuthorizationAlreadyUsed`, moves nothing and checks neither signature nor value (found
  by the fork suite on chain 4663, not by local mocks). So the settler checks
  `authorizationState(from, nonce)` first and reverts `AuthorizationUsed`, and every pull
  (`create`, `enter`, `enterWithAuthorization`) goes through `_pullExact`, which reverts
  `NotPaid` unless the settler's USDG balance rose by the amount.
- The internal `_enter(owner, marketId, outcome, amount)` is shared by `enter`
  (owner = `msg.sender`, pulls with `transferFrom`) and `enterWithAuthorization`
  (owner = `from`, pulls with the authorization). The mechanism code path is identical.
- Wallets sign USDG's EIP-712 domain, which must be **hardcoded** because USDG has no
  `eip712Domain()`: `{ name: "Global Dollar", version: "1", chainId: 4663,
  verifyingContract: 0x5fc5360D0400a0Fd4f2af552ADD042D716F1d168 }`
  (`DOMAIN_SEPARATOR` `0x7a3d7400…b62036`, recomputed and matched).
- The exact selector of the `bytes` overload is confirmed with
  `cast call USDG "getFacet(bytes4)(address)" <selector>` before S1 closes; if only
  the `(v, r, s)` overload is routed, the function takes `uint8 v, bytes32 r, bytes32 s`
  instead and smart-wallet bettors use `approve` + `enter`.
- `enterWithPermit` (EIP-2612) is **not** built: it would still need the bettor to send
  a transaction.

### D6 · Views the venue needs

```solidity
/// Win payout of a finalized position if its outcome won now: s·(S + A_o(now) − entryAcc)/S.
/// Monotone non-decreasing in time while the market is open (P2). 0 if not finalized.
function accrued(uint256 positionId) external view returns (uint256);

/// Positions of one market (ids are global); pagination for the venue's reader.
function marketPositions(uint256 marketId, uint256 from, uint256 count)
    external view returns (uint256[] memory ids);

/// Fee a claim would take right now (0 unless resolved and winning).
function previewFee(uint256 positionId) external view returns (uint256);
```
`marketPositions` requires a per-market index `uint256[] marketPositionIds[marketId]`
pushed in `enter` and in the seed; it is write-only bookkeeping and does not touch the
mechanism (covered by the differential test because it changes no returned value).

### D7 · Events for the indexer

Reference events are kept unchanged. Added: `FeeAccrued`, `FeesSwept`,
`EntriesPaused`. `Entered` already carries `(marketId, positionId, owner, outcome,
offered, vintage)`; the venue joins `block.timestamp` from the log's block.

### D8 · Settlement finalizes the last vintage, even in the same block

Added during the build (2026-09-28) after a reproduced fund drain. On Robinhood Chain
`block.number` is the L1 estimate (~12 s), so a market can be resolved or voided in the
same `block.number` as its last entry. The reference only finalizes a vintage whose block
has passed, so it would settle with that vintage still pending: a claim then refunds the
pending stake in full and a later `finalizeVintage` vests the same stake into the winners
again, paid out of other markets' escrow (`test/SameBlockSettlement.t.sol` drains 1,000
USDG from a victim market on the reference). Fix: `resolve` and `voidMarket` finalize an
open vintage unconditionally (one line each). Identical to the reference whenever the
block has advanced; safe in the same block because no entry can join after the freeze.

### D9 · Lock prevention (vintage entry and work caps, κ bound)

Added during the build after a reproduced permanent lock. Finalizing a vintage costs about
34k gas per entry and every exit from a market finalizes first; about 1,000 minimum entries
in one L1 block push finalization past the chain's 32M per-transaction gas limit, and the
market (with every stake in it) can never settle (`test/VintageStuffing.t.sol`). Fix:
`MAX_VINTAGE_ENTRIES = 200`; a 201st entry in the same vintage reverts `VintageFull()` and
the relayer retries it in the next block (the signed authorization stays unused, because
every check runs before the pull). A full vintage finalizes in about 6.9M gas. Because
finalization costs O(entries × outcomes) and `create` allows up to 255 outcomes, a second
cap `MAX_VINTAGE_WORK = 12,800` bounds `(pending + 1) × n` (200 entries up to 64 outcomes,
50 at 255); the fullest vintage of any creatable market finalizes in at most ~23.1M gas.
A finite κ above `MAX_KAPPA = 1e9` is refused at creation (`InvalidKappa`): a huge κ
overflows `κ · a` at finalization and would lock the market. (The published vectors use κ up
to 1e9.)

### D10 · Pre-deploy hardening (factory-only creation, pauser, finalized claims)

Added after the second review of 2026-09-28, before the first deploy. Every market pays out
of one escrow, and the reference lets anyone create a market with any token, outcome count,
κ, seed and resolver, so an accounting bug reachable only with odd parameters (F1 was one;
the review built two more locks, an unbounded κ with a lopsided seed overflowing the
128-bit entry accumulator and a finite κ on a huge-supply token) would reach the venue's
markets. The venue lists only binary κ = 30 USDG markets through its factory.

- `create` reverts `NotFactory()` unless `msg.sender == factory` (immutable, set in the
  constructor), and `EntriesArePaused()` while paused: no new seed into a paused venue.
- `pauser` (storage, `setPauser(address)` by the guardian only, `PauserSet(address)`) may
  call `setEntriesPaused(true)` and nothing else. A multisig pause needs a quorum; the
  pauser is one key kept offline (by default the deployer's), for an incident. A leaked
  pauser key can only pause; the guardian removes it and resumes.
- `_claim` reverts `NotFinalized()` for a position whose vintage is not finalized. D8 makes
  this unreachable; the check keeps a claim from ever paying a pending stake back as a
  refund (F1) if anything ever broke D8. It reads a slot the claim already loads.

### Unchanged from the reference (do not touch)

Rule 1 / Rule 2 arithmetic, `_seedClamp`, `_seedVintage`, `_finalizeVintage`, the
accumulator scale `SCALE = 1e18`, `KAPPA_UNBOUNDED`, block-vintage batching, the freeze,
`resolve` / `voidMarket` semantics (resolver-only resolve, resolver-or-timeout void),
`claimResidue`, `transferPosition`, storage packing of `Position`, `nonReentrant`.

## StockRoundResolver.sol — UP/DOWN from two proven Chainlink rounds

Replaces hunch-vpm's `FeedResolver` for stock markets. `FeedResolver` reads the
**latest** price at call time; a stock market must settle on the price **in effect at
the bell**, proven by round id, so that when the call is made (or who makes it) cannot
change the answer. No owner. No admin. No price input.

### Why "the price in effect at T", not "a print at T"

The Robinhood Chain equity feeds (8 decimals) are deviation-triggered: they update when
the price moves 0.5% from the last report, or on a 24 h heartbeat, across the 24/5
window (Sun 20:00 ET to Fri ~20:00 ET; overnight, pre-market, regular and post-market
sessions). A round printed exactly at 09:30 or 16:00 ET almost never exists; SPY's
Friday value "at 16:00" was 3 h 57 m old on 2026-09-25 (`research-facts.md` §10). So
both readings are defined as **the answer of the last round with `updatedAt ≤ T`**,
which is Chainlink's attestation of the price in effect at T, within its 0.5%
deviation band. The rules box says so, including that it can differ from the exchange's
official print by up to about 0.5%, and that the price is the **Stock Token's**
(share price × `uiMultiplier`), which stays continuous through splits and dividends.

### Spec

```solidity
struct Spec {
    address settler;      // HunchVPM
    uint256 marketId;
    address feed;         // Chainlink AggregatorV3 proxy (standard, not SVR), chain 4663
    address stockToken;   // the Robinhood Stock Token the feed prices (for oraclePaused())
    uint64  strikeTime;   // e.g. the opening bell, 09:30 ET, in unix seconds
    uint64  finalTime;    // e.g. the closing bell, 16:00 ET (== the market's freeze)
    uint32  maxStrikeAge; // strikeTime − updatedAt(strike round) must be ≤ this
    uint32  maxFinalAge;  // finalTime  − updatedAt(final round)  must be ≤ this
}
specId = keccak256(abi.encode(spec))   // immutable once registered
```
`register(Spec)` is callable only by the market's **creator** (the factory, which creates
and registers in one transaction), once per (settler, marketId). A permissionless
first-come `register` would let anyone front-run the spec of a market created outside the
factory. It checks `strikeTime < finalTime`, non-zero addresses, a binary open market, and
that the settler's market has `resolver == address(this)` and `resolutionTime == finalTime`.

### Proof that round `x` is "the last round at or before T"

- `updatedAt(x) ≤ T` and `updatedAt(x) > 0`.
- Once `x` is proven the round in effect (all the rules below), its answer must be inside a
  sanity band (`0 < answer < 1e14` at 8 decimals; SPY's first 7 rounds hold 18-decimal
  garbage, so historical rounds are never trusted blindly), else `BadAnswer`: the market
  cannot resolve and `voidBadAnswer` refunds it at once. The band is checked after the
  proof, not before (second review, L-3): checked first, a garbage answer on the round in
  effect made the market unprovable and left only the 72 h timeout. A garbage round that is
  not in effect is `BadProof` like any other.
- and either `updatedAt(x + 1) > T`, or round `x + 1` does not exist and `x` is the
  proxy's current `latestRoundData().roundId` (possible only because resolution runs at
  `block.timestamp ≥ T`: a round written later has `updatedAt > T`).
- Round ids are proxy ids (`phaseId << 64 | aggregatorRoundId`); `x + 1` is taken in the
  same phase. **Across phases the rule is: the last round at or before T of the highest
  phase that has any round at or before T.** A round in phase p is accepted only if every
  phase from p + 1 up to the proxy's current phase has its first round absent or after T.
  When Chainlink moves a proxy to a new aggregator, the new one usually reports before it
  is confirmed and the old one keeps its history, so two phases overlap in time; without
  this rule a caller could pick whichever phase's round gave the outcome they wanted (found
  by the independent review, `test/PhaseOverlap.t.sol`). A round more than
  `MAX_PHASE_SPAN = 8` phases below the current one reverts `PhaseBoundary` (the keeper
  pages the operator; the 72 h settler timeout remains the backstop). Residual: if
  Chainlink confirms, after a bell, an aggregator that had already reported before it, the
  provable pair switches at that moment; the first settlement is final.
- Resolution requires `block.timestamp > T` strictly, so no round written later can
  carry `updatedAt ≤ T`. An unreadable `oraclePaused()` counts as paused.
- A missing round (proxy reverts "No data present" or returns `updatedAt == 0`) is read
  with `try/catch` and treated as absent.

### Functions

```solidity
function resolve(bytes32 specId, uint80 strikeRound, uint80 finalRound) external;
```
Anyone, at `block.timestamp > finalTime`. Verifies both proofs (`strikeRound` for
`strikeTime`, `finalRound` for `finalTime`, `finalRound ≥ strikeRound`), then:
- `IStockToken(stockToken).oraclePaused()` is true → revert `OraclePaused` (Robinhood's
  corporate-action flag; wait, see `voidPaused`);
- `strikeTime − updatedAt(strike) > maxStrikeAge` or `finalTime − updatedAt(final) >
  maxFinalAge` → revert `Stale` (use `voidStale`; `resolve` never voids for staleness,
  so a mistaken call cannot destroy a good market);
- same round, or `answer(final) == answer(strike)` → `settler.voidMarket(marketId)`
  (FLAT: the price did not move enough for Chainlink to report a change; full refund,
  no fee);
- `answer(final) > answer(strike)` → `settler.resolve(marketId, 0)` (UP);
- `answer(final) < answer(strike)` → `settler.resolve(marketId, 1)` (DOWN).
Emits `Resolved(specId, marketId, outcome /*0 UP, 1 DOWN, 2 FLAT*/, strikeRound,
strikeAnswer, strikeAt, finalRound, finalAnswer, finalAt)`.

```solidity
function voidStale(bytes32 specId, uint80 strikeRound, uint80 finalRound) external;
```
Anyone, at `block.timestamp > finalTime`. Verifies the **same proofs**, then requires
that an age bound is actually violated; otherwise reverts `NotStale`. Nobody can void a
market that has a good answer.

```solidity
function voidBadAnswer(bytes32 specId, uint80 strikeRound, uint80 finalRound) external;
```
Anyone, at `block.timestamp > finalTime`. Both rounds must prove as the rounds in effect,
exactly as for `resolve`, and at least one answer must be outside the band; otherwise it
reverts (`BadProof` / `PhaseBoundary`, or `NotBadAnswer`). Emits
`VoidedBadAnswer(specId, marketId, strikeRound, finalRound)` and voids the market.

```solidity
function voidPaused(bytes32 specId) external;
```
Anyone, at `block.timestamp ≥ finalTime + 24 h`, if `oraclePaused()` is still true.

Safety net: if nobody resolves or voids, HunchVPM's own `voidTimeout` (72 h) lets anyone
void the market directly.

```solidity
function preview(bytes32 specId, uint80 strikeRound, uint80 finalRound)
    external view returns (uint8 status /*0 notReady 1 UP 2 DOWN 3 FLAT 4 STALE 5 BADPROOF 6 PAUSED 7 BADANSWER*/,
                           int256 strikeAnswer, uint256 strikeAt,
                           int256 finalAnswer, uint256 finalAt);
```
Used by the keeper and by the `/proof` page's "Resolve it yourself" button.
`settled[specId]` is set before calling the settler; a second call reverts
`AlreadySettled`.

### Round finding (off-chain, keeper + web)

`findLastAtOrBefore(feed, t)`: read `latestRoundData`, walk back with `getRoundData`
(binary search inside the current phase, ≤ ~20 reads), fall back to `AnswerUpdated`
logs on the aggregator (`eth_getLogs` over ~5.8 days returns ~32 NVDA logs, verified).
Pure TypeScript in `packages/client/src/rounds.ts`, unit-tested against round series
captured from chain 4663 (never hand-written; `07-testing.md` T8r). Needs a keyed RPC:
the public RPC keeps only ~10 minutes of historical state.

### Corporate actions

- The feed prices the token: share price × `uiMultiplier`, which Robinhood updates on
  dividends and splits, so the series stays continuous and UP/DOWN remains meaningful
  across a split. The rules box says "the Stock Token's price per Chainlink", never
  "the NYSE close".
- `oraclePaused()` is Robinhood's corporate-action flag on every Stock Token
  (Beacon-proxied `Stock` implementation, verified ABI). It blocks resolution while set
  and voids after 24 h.
- The keeper also skips listing a ticker whose window contains an announced split
  (`keeper/calendar/corporate-actions.json`), because the pause can be long.

## HunchMarketFactory.sol — list a market in one transaction

Adapted from hunch-vpm `MarketFactory` (seed pull, create, register, hand-over, refund
unused).

```solidity
constructor(HunchVPM settler, StockRoundResolver resolver, IERC20 usdg, address owner_, address treasury_)

struct UpDown {
    address feed;          // must be allow-listed (the Stock Token comes from the allow-list)
    uint64  strikeTime;
    uint64  finalTime;
    uint32  maxStrikeAge;  // 0 = the feed's allow-listed bound; otherwise must be ≤ it
    uint32  maxFinalAge;   // same rule: an opener may only TIGHTEN a bound, never loosen it
    uint128 seedPerLeg;    // 10e6 = 10 USDG
    uint128 minEntry;      // 1e6
    uint128 maxEntry;      // 100e6
}

function openUpDown(UpDown calldata p) external onlyOpener
    returns (uint256 marketId, bytes32 specId);
```
Checks: feed allow-listed; `block.timestamp < strikeTime < finalTime` (a market is listed
before its strike bell, so nobody bets on a strike price already known; second review, L-4);
`finalTime − strikeTime ≤ 8 days`; `seedPerLeg ≥ 1e6`; each requested age bound is 0
or ≤ the allow-listed one. Then: pull `2 · seedPerLeg` USDG
from the opener, approve the settler, `create(usdg, [seed, seed], kappa = 30, finalTime,
voidTimeout = 72 h, resolver, residueOwner = treasury, feeBps = 200, minEntry,
maxEntry)`, `register` the spec with the feed, its Stock Token and the effective age bounds, transfer
both seed positions to the **opener** (so the seed float recycles to the keeper wallet on
every settlement without a daily Safe transaction), zero the allowance, return any
refused seed. Residue and fees still go to the treasury Safe.
Emits `MarketOpened(marketId, specId, feed, ticker, strikeTime, finalTime, seedPerLeg,
minEntry, maxEntry)`.

Owner-only (the Safe, two-step ownership transfer):
- `setFeed(address feed, address stockToken, string ticker, uint32 maxStrikeAge, uint32 maxFinalAge, bool allowed)`
- `setOpener(address opener, bool allowed)`

The factory holds no funds between transactions (asserted by test).

## Powers, stated once (this table goes into the README verbatim)

| Who | Can | Cannot |
|---|---|---|
| Safe (guardian of HunchVPM) | pause and resume **new entries and new markets**; name or remove the pauser | pause or block claims, refunds, resolution; move any stake; set any price |
| Pauser (one key the Safe names) | pause **new entries and new markets** | resume them; anything else |
| Safe (owner of factory) | allow-list a feed, its Stock Token and its staleness bounds; add/remove an opener | change a listed market's feed, times, bounds, seed, fee or caps |
| Opener (keeper hot wallet) | list a new market through the factory (the only creator HunchVPM accepts), paying the seed itself; owns the seed legs it paid for | change or close an existing market; touch anyone else's position |
| Anyone | resolve with the two proven rounds; void on proven staleness, a proven out-of-range price or a 24 h oracle pause; relay a bettor's signed entry; deliver claims and refunds to owners; sweep fees to the treasury | choose the outcome; send anyone's funds anywhere but to their owner |
| StockRoundResolver | settle its registered markets per the spec | anything else (it has no owner) |

## Invariants (asserted by the invariant suite, `07-testing.md` T4)

- **INV-1 Solvency.** `usdg.balanceOf(HunchVPM) ≥ Σ open-market escrow + Σ unclaimed
  payouts + Σ unwithdrawn refunds + Σ unclaimed residue + feesAccrued`.
- **INV-2 Conservation.** For a resolved market, `Σ payouts + residue == acceptedPool`
  and `Σ fees ≤ Σ (payout − accepted)·feeBps/1e4` over winners. For a voided market,
  `Σ refunds of accepted == acceptedPool`.
- **INV-3 Exits.** Only `claim*`, `withdrawRefund*`, `claimResidue`, `sweepFees` move
  tokens out, to the position owner, the residue owner or the treasury respectively.
- **INV-4 Pause scope.** While paused, only entries fail.
- **INV-5 Monotone accrual (P2).** For every finalized open position, `accrued(id)` never
  decreases across any sequence of later entries.
- **INV-6 Reference equivalence.** Fee 0 / no bounds ⇒ identical outcomes to the reference.
- **INV-7 Resolver soundness.** `resolve` succeeds only with the unique pair defined
  above (the last round at or before T of the highest phase with one), including when
  phases overlap in time; any other pair reverts.
- **INV-8 Signed entries.** An `enterWithAuthorization` whose market, side, amount or
  salt differs from what was signed reverts; a used authorization cannot be replayed.
